# 캠퍼스 비서 (데모)

국민대학교 AWS 해커톤용 **대학생 맞춤 공지·일정 추천 서비스**의 모바일 웹 데모입니다.
흩어진 공지에서 전공·학년·관심사·목표에 맞는 기회를 추천하고, 저장·일정 추가까지 눌러볼 수 있습니다.

> 이 앱은 **데모**입니다. 실제 로그인, AI, 크롤링, 구글 캘린더 연동 없이 예시 데이터와 브라우저 저장소(localStorage)만으로 동작합니다.

---

## 1. 실행 / 미리보기 방법

### 준비물
- 이 컴퓨터에는 Node.js가 이미 설치되어 있습니다.
- Windows PowerShell에서 npm 스크립트 실행이 막혀 있을 수 있어, 아래 명령을 **한 번** 실행해 현재 창에서만 허용합니다.

### 개발 서버 실행 (검토용, 추천)
PowerShell을 열고 이 폴더에서 아래를 순서대로 입력하세요.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
npm install        # 처음 한 번만
npm run dev
```

- 실행되면 터미널에 `http://localhost:5173/` 주소가 나옵니다.
- 브라우저에서 이 주소를 엽니다.
- **모바일 화면으로 보는 법**: 브라우저에서 `F12`(개발자 도구) → 왼쪽 위 휴대폰 모양 아이콘 클릭 → 기기 폭을 **390px** 정도로 맞추면 실제 휴대폰처럼 보입니다.

### 종료
- 터미널에서 `Ctrl + C` 를 누르면 서버가 꺼집니다.

## 2. 검토할 주요 동작 (핵심 흐름)

아래 순서대로 눌러보면 전체 흐름을 확인할 수 있습니다.

1. **예시 프로필로 시작하기** — 첫 화면에서 버튼 한 번으로 시작 (전자공학부·3학년·반도체 등)
2. **맞춤 추천 확인** — 홈에서 추천 카드와 "추천 이유"가 바로 보임
3. **필터 적용** — 교육/채용/대외활동/장학금, 온라인만·무료만·주말만, 추천순·마감 임박순
4. **상세 보기** — 카드를 누르면 추천 이유, 지원 자격, 비용, 마감/행사 일정 확인
5. **공지 저장** — 상세 하단 또는 카드의 북마크 아이콘
6. **구글 캘린더 데모 연결** — 하단 "내 일정" 탭 → "구글 캘린더 데모 연결하기"
7. **기존 일정 확인** — 연결하면 예시 수업·약속이 보임
8. **추천 일정 추가** — 상세 → "일정에 추가" → 신청 마감 / 행사 일정 / 둘 다 선택
9. **충돌 안내 확인** — 행사 시간이 기존 수업과 겹치면 경고가 뜸 (확인 후에도 추가 가능)
10. **알림 선택값 저장** — 알림 없음 / 1시간 전 / 하루 전
11. **내 일정에서 확인** — 추가한 일정이 날짜별로 표시됨

추가로 확인해볼 만한 것:
- **관심 없음 → 실행 취소**: 카드의 X 버튼으로 숨기고, 하단 토스트의 "실행 취소"로 복구
- **프로필 변경 → 추천 변화**: 프로필 탭에서 관심 분야를 바꾸면 추천 순서·이유가 달라짐
- **중복 방지**: 같은 공지의 같은 일정 유형은 두 번 추가되지 않음 (마감만 추가 후 행사는 나중에 추가 가능)
- **새로고침 유지**: 브라우저를 새로고침해도 프로필·저장·일정이 그대로 남음
- **전체 초기화**: 프로필 탭 → 설정 → "전체 데모 초기화"로 처음 상태로 되돌림

## 3. 현재 "시뮬레이션(가짜)"인 기능

실제 서비스처럼 보이지만 데모에서는 흉내만 내는 부분입니다. 앱 안에도 안내 문구가 있습니다.

- **구글 캘린더 연결**: 실제 구글 로그인/권한 요청 없음. 미리 만든 예시 일정을 보여줄 뿐이며 "데모 연결됨"으로 표시됩니다.
- **새로고침**: 실제 서버 동기화가 아니라 예시 데이터를 다시 불러오는 동작입니다.
- **알림(1시간 전/하루 전)**: 선택값은 저장되지만 **실제 알림은 발송되지 않습니다.**
- **신청 페이지 열기**: 예시 공지라서 실제 신청 링크가 없습니다. 누르면 안내만 표시됩니다.
- **추천**: AI가 문장을 이해하는 방식이 아니라, 전공·학년·관심 태그·목표를 기준으로 한 **간단한 규칙**입니다. 추가 맥락(자유 입력)은 저장·표시만 하고 추천 판단에는 쓰지 않습니다.
- **관심 없음**: AI 학습이 아니라 해당 공지를 숨기는 기능입니다.
- **공지 데이터**: 국민대 실제 공지 흐름을 참고해 재구성한 예시 12~15개이며, 날짜는 처음 실행한 날을 기준으로 자동 생성됩니다.

## 4. 실제로 검증한 항목 / 검증하지 못한 항목

### 검증한 항목
- **빌드 통과**: `npm run build` 성공 (타입 오류 없음, `dist/` 산출물 생성 확인).
- **개발 서버 정상 구동**: `http://localhost:5173/` 및 앱 진입점이 정상 응답(HTTP 200) 확인.
- **핵심 로직**: 추천 규칙(자격 미충족·마감 공지 제외), 일정 중복 방지, 시간 없는 일정의 알림 처리, 충돌 검사 로직을 코드로 구현·검토.

### 검증하지 못한 항목 (수동 확인 권장)
- **실제 브라우저에서의 시각적 검토**: 자동화된 화면 캡처 검토는 하지 못했습니다. 위 2번 흐름을 **390px 폭**에서 직접 눌러보며 확인해 주세요.
- 특히 아래를 눈으로 확인하면 좋습니다.
  - 하단 플로팅 내비게이션이 마지막 카드를 가리지 않는지
  - 공지 상세의 하단 버튼(저장·신청·일정 추가)이 내비게이션과 겹치지 않는지 (상세에서는 탭 바가 숨겨집니다)
  - 작은 화면에서 글자·버튼이 잘리지 않는지
- **다양한 실기기/브라우저 호환성**: 크롬 데스크톱 기준으로만 구성했습니다.

## 5. 폴더 구조 (참고)

```
src/
  data/        예시 데이터·타입·날짜 계산·추천 규칙·저장소 (UI와 분리)
  components/  공용 UI (아이콘, 하단 내비, 토스트, 바텀시트)
  screens/     화면별 컴포넌트 (홈/상세/저장/내일정/프로필/온보딩)
  store.tsx    앱 상태 + localStorage 연동
  App.tsx      화면 전환(라우팅)
```

실제 API(로그인·AI·크롤링·구글 캘린더)를 나중에 붙이기 쉽도록, 예시 데이터와 데이터 처리 함수는 `src/data/`에 모아 UI와 분리했습니다.

## 6. (nykim 브랜치) 실제 Google 로그인 · Calendar 연동 백엔드

`nykim` 브랜치에는 데모를 넘어 **실제 Google OAuth 로그인**과 **Google Calendar 일정 생성**을
처리하는 백엔드(Node.js + Express + TypeScript)가 추가되었습니다. 프론트엔드 UI/공지 데이터/
일정 선택 화면은 그대로 유지됩니다.

### 폴더 구조 (추가분)

```
server/                 백엔드 (Express + TypeScript)
  src/
    index.ts            앱 진입점 (127.0.0.1:4000 내부 전용)
    config.ts           환경변수 / OAuth scope
    session.ts          파일 기반 세션 (MemoryStore 아님)
    middleware/         requireAuth
    google/             oauthClient · userInfo · calendar (googleapis)
    notices/            datetime(KST) · repository(공지 검증, src/data/notices.data.json 재사용)
    calendar/           buildEvent (일정 유형/날짜 규칙)
    store/              tokenStore (토큰·생성이력 JSON 저장, 토큰 암호화)
    routes/             auth · calendar
  .env.example          백엔드 환경변수 예시
deploy/
  nginx.conf.example        Nginx 리버스 프록시 + SPA fallback + HTTPS
  campus-secretary.service  systemd 서비스 (재시작 자동 실행)
  DEPLOY.md                 EC2 배포 가이드 (단계별)
```

### 로컬에서 함께 실행하기

```powershell
# 1) 백엔드 (터미널 A)
cd server
npm install
# server/.env 를 .env.example 보고 작성 (Google 자격증명 없으면 로그인만 비활성)
npm run dev            # http://127.0.0.1:4000

# 2) 프론트엔드 (터미널 B)
npm run dev            # http://localhost:5173  (/api 는 4000 으로 자동 프록시)
```

- 프론트엔드 `/api` 요청은 Vite 프록시가 백엔드(4000)로 전달합니다. (운영에선 Nginx 가 담당)
- **Google Cloud 자격증명이 없으면** 로그인 버튼은 비활성화되고, 그 외 화면은 정상 동작합니다.
- 실제 로그인·캘린더 저장은 Google Cloud 설정 + HTTPS 도메인 준비 후 동작합니다. 자세한 내용은
  `deploy/DEPLOY.md` 를 참고하세요.

### 데모와 실제의 구분

- **실제 연동**: 구글 로그인(서버 세션), 공지 일정을 내 구글 캘린더 primary 에 생성.
- **여전히 데모**: "내 일정" 화면의 *예시 일정 미리보기*(구글 캘린더 예시 데이터), 추천/AI, 알림 발송.
- 앱은 실제 저장에 성공한 경우에만 성공 메시지를 표시하며, 저장된 일정은 "구글 캘린더에서 열기"
  링크를 제공합니다. 앱에서 일정을 삭제해도 **구글 캘린더의 실제 일정은 삭제되지 않습니다.**
